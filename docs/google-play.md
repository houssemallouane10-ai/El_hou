# نشر خدمتي على Google Play — دليل خطوة بخطوة

خدمتي تطبيق ويب تقدّمي (PWA). على Google Play يصبح **تطبيق أندرويد خفيفًا (Trusted Web Activity)** يفتح موقعك
بملء الشاشة، بدون شريط المتصفح، وبأيقونته الخاصة. ميزة كبيرة: **كل تحديث تنشره على الخادم يصل فورًا لكل المستخدمين**
دون رفع نسخة جديدة على المتجر.

الترتيب مهم:

1. انشر الموقع على دومين باسمك مع HTTPS.
2. اجعل نفسك المالك (لوحة الإدارة).
3. اصنع حزمة أندرويد بـ PWABuilder.
4. اربط التطبيق بالموقع (assetlinks).
5. أنشئ التطبيق في Play Console واملأ البطاقة والاستمارات.
6. اختبار مغلق: 12 مختبرًا لمدة 14 يومًا (للحسابات الشخصية الجديدة).
7. النشر للجميع.

---

## 0. ما تحتاجه

| الحاجة | ملاحظات |
| --- | --- |
| خادم بـ Node.js 20 أو Docker، مع **قرص دائم** | VPS (Hetzner، OVH، Contabo…) أو Railway / Render / Fly.io مع Volume |
| دومين باسمك و HTTPS | مثلًا `khedmati.com`. HTTPS إلزامي للتطبيق |
| حساب Google Play Console | 25 دولارًا مرة واحدة، بطاقة Visa أو Mastercard دولية باسمك (البطاقات المسبقة الدفع مرفوضة) وبطاقة تعريف للتحقق من هويتك |
| هاتف أندرويد | للتجربة قبل النشر |
| 12 شخصًا على الأقل | مختبرون لمدة 14 يومًا متتالية (العائلة والأصدقاء) |

## 1. انشر الموقع

اتبع قسم «النشر على الإنترنت» في [README](../README.md). متغيرات البيئة المهمة للإنتاج:

```bash
NODE_ENV=production
PUBLIC_URL=https://YOUR-DOMAIN
TRUST_PROXY=1
DATA_DIR=/data                    # على قرص دائم
ADMIN_PHONES=06XXXXXXXX           # رقمك أنت: المالك
SUPPORT_WHATSAPP=06XXXXXXXX       # يظهر في «نسيت كلمة السر» وفي صفحات الخصوصية وحذف الحساب
SUPPORT_EMAIL=you@example.com     # بريد التواصل
```

تأكد أن هذه الروابط تفتح بدون مشاكل (يراجعها Google):

- `https://YOUR-DOMAIN/privacy` — سياسة الخصوصية
- `https://YOUR-DOMAIN/terms` — شروط الاستخدام
- `https://YOUR-DOMAIN/account-deletion` — حذف الحساب (إلزامي في Google Play)

> الصفحات الثلاث تُعرض كاملة حتى بدون JavaScript، والتواصل (واتساب والبريد) يظهر فيها تلقائيًا.

## 2. أنت المالك: لوحة الإدارة وكل الصلاحيات

- ضع رقمك في `ADMIN_PHONES` ثم **سجّل في التطبيق بنفس الرقم**. ستجد «لوحة الإدارة» في «حسابي».
- الأرقام الموجودة في `ADMIN_PHONES` هي **المالكون**: مشرفون دائمًا، ولا أحد يستطيع سحب صلاحياتهم من التطبيق.
- **المالك وحده** يعيّن المشرفين أو يزيلهم: لوحة الإدارة ← المستخدمون ← «تعيين مشرفًا».
- المشرفون يعالجون البلاغات، يحجبون العروض، يحظرون الحسابات ويوثّقونها، ويعطون كلمة سر مؤقتة لمن نسيها.
- «نظرة عامة» تعرض الأرقام وجدول **النشاط حسب الولاية**؛ والقوائم تُصفّى حسب الولاية.
- إن نسيت كلمة سرك أنت: على الخادم نفّذ `npm run reset-password -- 06XXXXXXXX` لتحصل على كلمة سر مؤقتة.

## 3. اصنع حزمة أندرويد بـ PWABuilder

1. افتح [pwabuilder.com](https://www.pwabuilder.com) وأدخل رابط موقعك ثم **Start**.
2. اختر **Package for stores → Android → Generate Package** (نوع Google Play).
3. الإعدادات:

   | الحقل | القيمة المقترحة |
   | --- | --- |
   | Package ID | `dz.khedmati.app` (أو `com.اسمك.khedmati`) — **لا يتغير أبدًا بعد النشر** |
   | App name / Launcher name | خدمتي |
   | Version / Version code | `1.0.0` / `1` (زِد رقم الـ code في كل رفع جديد) |
   | Host / Start URL | دومينك / `/?source=twa` |
   | Theme / Background color | `#0a7a55` / `#f5f7f4` |
   | Signing key | **Create new** |

4. حمّل الملف المضغوط. بداخله:
   - `*.aab` — هذا ما ترفعه إلى Google Play.
   - `*.apk` — لتجربته مباشرة على هاتفك.
   - `signing.keystore` و `signing-key-info.txt` — **مفتاح التوقيع وكلمات سره**.

> ⚠️ احفظ `signing.keystore` و `signing-key-info.txt` في مكانين آمنين (مثلًا Google Drive + فلاشة). كل تحديث مستقبلي
> للتطبيق يجب أن يُوقَّع بنفس المفتاح.

> منذ أوت 2026 يشترط Google Play أن تستهدف التطبيقات الجديدة Android 16 (API 36)، وحِزم PWABuilder تستهدفه منذ 7 أوت 2026.
> Google يرفع هذا الشرط كل سنة في أوت: عندها أعد التوليد بـ PWABuilder **بنفس الـ Package ID ونفس المفتاح** ورقم version code أكبر.

## 4. اربط التطبيق بالموقع (Digital Asset Links)

بدون هذه الخطوة يظهر شريط عنوان المتصفح أعلى التطبيق.

1. انسخ بصمة SHA-256 من `signing-key-info.txt` (بصمة مفتاح الرفع).
2. بعد إنشاء التطبيق في Play Console (الخطوة 5) انسخ بصمة **App signing key certificate** من
   **Test and release → Setup → App integrity → App signing** (في بعض الواجهات: **Release → Setup → App integrity**).
   Google يعيد توقيع التطبيق بهذا المفتاح، لذا هي الأهم.
3. ضع القيمتين على الخادم وأعد تشغيله:

   ```bash
   ANDROID_PACKAGE_NAME=dz.khedmati.app
   ANDROID_SHA256_FINGERPRINTS=AA:BB:...:FF,11:22:...:99
   ```

4. تحقق: `https://YOUR-DOMAIN/.well-known/assetlinks.json` يجب أن يعرض اسم الحزمة والبصمتين.
   الخادم يرفض الإقلاع إن كانت البصمة مكتوبة بشكل خاطئ (32 زوجًا من الأحرف مفصولة بنقطتين).

## 5. Play Console

### أ. الحساب والتطبيق
1. أنشئ حساب مطوّر على [play.google.com/console](https://play.google.com/console) (حساب **شخصي**)، ادفع 25 دولارًا وأكمل التحقق من الهوية.
2. **Create app**: الاسم «خدمتي»، اللغة الافتراضية **العربية**، النوع **App**، **Free**.

### ب. بطاقة المتجر
- النصوص الجاهزة بالعربية والفرنسية: [`store/listing.md`](../store/listing.md) (تحقق من الطول بـ `npm run check-listing`).
- الصور الجاهزة:
  - الأيقونة: `store/icon-512.png`
  - صورة العرض: `store/feature-graphic.png`
  - لقطات الهاتف: `store/screenshots/` (7 لقطات 1080×1920)
- التصنيف: **Business**.

### ج. محتوى التطبيق (App content)
كل الإجابات جاهزة في [`store/data-safety.md`](../store/data-safety.md): سياسة الخصوصية، الإعلانات (لا)، الوصول للتطبيق
(أعطِ المراجع حسابًا تجريبيًا)، تصنيف المحتوى، الجمهور المستهدف (**18 سنة فما فوق**)، أمان البيانات، ورابط حذف الحساب.

### د. ما يشترطه Google في التطبيقات التي ينشر فيها المستخدمون محتوى — موجود في خدمتي
- قبول شروط الاستخدام قبل إنشاء الحساب (خانة إلزامية).
- الإبلاغ عن العروض والحسابات والمحادثات.
- حظر المستخدمين في الرسائل الخاصة، وقائمة المحظورين في الإعدادات.
- حذف الحساب من داخل التطبيق ومن رابط على الويب.
- إشراف فعلي: **راجع البلاغات بانتظام** من لوحة الإدارة، فـ Google قد يتحقق من ذلك.

## 6. الاختبار المغلق (إلزامي للحسابات الشخصية الجديدة)

حسابات المطوّرين الشخصية التي أُنشئت بعد 13 نوفمبر 2023 لا تستطيع النشر للجميع قبل اختبار مغلق:
**12 مختبرًا على الأقل، مشتركين بلا انقطاع لمدة 14 يومًا**.

1. **Test and release → Testing → Closed testing → Create track**.
2. ارفع ملف `.aab` وأنشئ إصدارًا.
3. أضف المختبرين بعناوين Gmail (أو مجموعة Google Groups)، وأرسل لهم رابط الاشتراك.
4. كل مختبر: يفتح الرابط ← يقبل ← يثبّت التطبيق من Play Store ← **يستعمله ولا يلغي الاشتراك** طيلة 14 يومًا.
   خذ 14 أو 15 شخصًا احتياطًا: إن نزل العدد تحت 12 قد يعود العدّ من الصفر.
5. بعد 14 يومًا: **Dashboard → Apply for production** وأجب عن أسئلة الاختبار (ماذا جرّب المختبرون وماذا حسّنت).

> الحسابات من نوع **منظمة** (شركة لها رقم D-U-N-S) معفاة من هذا الشرط.

## 7. النشر للجميع

بعد الموافقة: **Production → Create new release** ← ارفع `.aab` (أو رقّ إصدار الاختبار) ← اختر الدول (الجزائر،
ويمكن إضافة دول أخرى) ← **Start rollout**. المراجعة تأخذ عادة من يوم إلى بضعة أيام.

## التحديثات بعد النشر

| ماذا غيّرت | ماذا تفعل |
| --- | --- |
| أي شيء في الموقع (ميزات، نصوص، تصميم، إصلاحات) | انشره على الخادم فقط. يصل للتطبيق فورًا |
| الاسم أو الأيقونة أو الألوان في حزمة أندرويد، أو شرط API السنوي | أعد التوليد بـ PWABuilder بنفس المفتاح، رقم version code أكبر، وارفعه |

## مشاكل شائعة

| المشكلة | الحل |
| --- | --- |
| شريط عنوان المتصفح يظهر أعلى التطبيق | بصمة App signing من Play Console غير موجودة في `ANDROID_SHA256_FINGERPRINTS`، أو `assetlinks.json` لا يفتح |
| «Your app must target Android 16 (API 36)» | أعد التوليد بآخر نسخة من PWABuilder |
| المراجع لم يستطع الدخول | ضع رقمًا وكلمة سر صالحين في App access |
| رفض بسبب المحتوى (UGC) | تأكد أن البلاغات تُعالج، وأن روابط الشروط والخصوصية وحذف الحساب تعمل |
| «You uploaded an APK or Android App Bundle that was signed in debug mode / with a different key» | استعمل نفس `signing.keystore` الأصلي |
